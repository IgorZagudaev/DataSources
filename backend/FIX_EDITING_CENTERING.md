# Исправление центрирования при редактировании

## Проблема

При нажатии на кнопку редактирования элемента, который находится ниже середины экрана, элемент "уезжал вниз" вместо правильного центрирования.

### Причина

Проблема возникала из-за последовательности событий:

1. Пользователь нажимает кнопку редактирования
2. Срабатывает `onSelect` → устанавливается `selectedId` → срабатывает центрирование (задержка 100мс)
3. Открывается вторая панель (форма редактирования) с анимацией `animate-slide-up` (300мс)
4. Вторая панель занимает 50% экрана снизу
5. Высота первой панели (дерева) уменьшается
6. Элемент, который был отцентрирован, теперь оказывается не в центре из-за изменения высоты контейнера

## Решение

Увеличена задержка перед центрированием при редактировании с 100мс до 400мс. Это дает время для завершения анимации появления второй панели (300мс) и перерасчета высоты контейнера.

### Изменения в коде

**Файл:** `src/components/TreeView.tsx`

**Было:**
```typescript
// Автоматическое центрирование редактируемой строки
useEffect(() => {
  if (!editingId || !treeContainerRef.current) return;

  // Небольшая задержка для завершения рендеринга
  setTimeout(() => {
    const editingElement = treeContainerRef.current?.querySelector(`[data-node-id="${editingId}"]`);
    if (editingElement) {
      editingElement.scrollIntoView({
        behavior: 'smooth',
        block: 'center'
      });
    }
  }, 100);  // ← Было 100мс
}, [editingId]);
```

**Стало:**
```typescript
// Автоматическое центрирование редактируемой строки
useEffect(() => {
  if (!editingId || !treeContainerRef.current) return;

  // Увеличенная задержка для завершения анимации появления второй панели
  setTimeout(() => {
    const editingElement = treeContainerRef.current?.querySelector(`[data-node-id="${editingId}"]`);
    if (editingElement) {
      editingElement.scrollIntoView({
        behavior: 'smooth',
        block: 'center'
      });
    }
  }, 400);  // ← Стало 400мс
}, [editingId]);
```

## Технические детали

### Последовательность событий при редактировании

```
T=0ms:    Пользователь нажимает кнопку редактирования
T=0ms:    Вызывается handleEdit() → устанавливается editingId
T=0ms:    Срабатывает useEffect для selectedId (если был выбран)
T=100ms:  Центрирование для selectedId (если был выбран)
T=300ms:  Завершается анимация появления второй панели
T=400ms:  Центрирование для editingId ← Исправлено
```

### Почему 400мс?

- Анимация появления второй панели: 300мс (CSS `animate-slide-up`)
- Дополнительный буфер: 100мс
- Итого: 400мс

Это гарантирует, что центрирование произойдет после завершения всех анимаций и перерасчета layout.

## Альтернативные решения

### Вариант 1: Использование ResizeObserver

Можно использовать `ResizeObserver` для отслеживания изменения размера контейнера:

```typescript
useEffect(() => {
  if (!editingId || !treeContainerRef.current) return;

  const observer = new ResizeObserver(() => {
    const editingElement = treeContainerRef.current?.querySelector(`[data-node-id="${editingId}"]`);
    if (editingElement) {
      editingElement.scrollIntoView({
        behavior: 'smooth',
        block: 'center'
      });
    }
  });

  observer.observe(treeContainerRef.current);

  return () => observer.disconnect();
}, [editingId]);
```

**Преимущества:**
- Более точное определение момента завершения анимации
- Автоматическая адаптация к любым изменениям размера

**Недостатки:**
- Более сложная реализация
- Возможны множественные срабатывания

### Вариант 2: Использование transitionend

Можно отслеживать завер CSS-переходов:

```typescript
useEffect(() => {
  if (!editingId || !treeContainerRef.current) return;

  const handleTransitionEnd = () => {
    const editingElement = treeContainerRef.current?.querySelector(`[data-node-id="${editingId}"]`);
    if (editingElement) {
      editingElement.scrollIntoView({
        behavior: 'smooth',
        block: 'center'
      });
    }
  };

  const panel = document.querySelector('.animate-slide-up');
  if (panel) {
    panel.addEventListener('transitionend', handleTransitionEnd);
    return () => panel.removeEventListener('transitionend', handleTransitionEnd);
  }
}, [editingId]);
```

**Преимущества:**
- Точное определение завершения анимации

**Недостатки:**
- Зависимость от DOM-структуры
- Сложность реализации

### Текущее решение (setTimeout)

**Преимущества:**
- Простота реализации
- Предсказуемость
- Надежность

**Недостатки:**
- Фиксированная задержка
- Может не сработать при очень медленных устройствах
