# Краткая инструкция: Оптимизация загрузки данных

## Проблема

**Сейчас:** При любом изменении загружаются ВСЕ данные из БД
```
Изменение источника → Загрузка 5 МБ данных → 2-5 секунд
```

**Оптимально:** Загружать только изменённую ветку иерархии
```
Изменение источника → Загрузка 1 КБ данных → 50-200 мс
```

---

## Решение: Частичная загрузка

### Архитектура

```
Изменение на уровне N
  ↓
Загрузка только уровня N и его предков
  ↓
Локальное обновление состояния
  ↓
Мгновенное обновление UI
```

### Пример

```typescript
// Было:
export async function updateSource(...) {
  await api.updateSource(...);
  await loadReports(); // ← Загрузка ВСЕХ данных (5 МБ)
}

// Стало:
export async function updateSource(...) {
  await api.updateSource(...);
  await loadHierarchy('source', sourceId); // ← Загрузка только ветки (1 КБ)
}
```

## Что нужно сделать

### 1. Новые API endpoints

```php
// Загрузка ветки иерархии
GET /api/sources/{id}/hierarchy
→ Возвращает: source + slice + indicator + note + section + report

// Загрузка дочерних элементов
GET /api/indicators/{id}/children
→ Возвращает: slices + sources
```

### 2. Изменения в store.ts

```typescript
// Новая функция
export async function loadHierarchy(level: string, id: string): Promise<void> {
  const hierarchy = await api.fetchHierarchy(level, id);
  reports = updateLocalState(reports, hierarchy);
  notify();
}

// Обновлённые CRUD функции
export async function updateSource(...) {
  await api.updateSource(...);
  await loadHierarchy('source', sourceId);
}
```

### 3. Изменения в api.ts

```typescript
export async function fetchHierarchy(level: string, id: string) {
  return apiRequest(`/${level}/${id}/hierarchy`);
}
```

## Преимущества

| Метрика | Сейчас | После оптимизации |
|---------|--------|-------------------|
| Время операции | 2-5 сек | 50-200 мс |
| Объём данных | 5 МБ | 1 КБ |
| SQL запросов | 10+ | 6 |
| Нагрузка на БД | Высокая | Минимальная |

---

## Сложности

1. **Синхронизация состояния** - нужно синхронизировать локальное состояние с БД
2. **Оптимистичные обновления** - UI обновляется до получения ответа
3. **Кэширование** - нужно кэшировать данные для повторных запросов
4. **Откаты** - нужно откатывать изменения при ошибках

## План реализации

### Фаза 1: API endpoints (1-2 дня)
- Создать `/api/{level}/{id}/hierarchy`
- Создать `/api/{level}/{id}/children`
- Тестирование

### Фаза 2: Частичная загрузка (2-3 дня)
- Реализовать `loadHierarchy()`
- Реализовать `updateLocalState()`
- Обновить CRUD функции

### Фаза 3: Оптимизации (1-2 дня)
- Добавить кэширование
- Добавить оптимистичные обновления
- Добавить периодическую синхронизацию

**Общее время:** 5-8 дней

## Заключение

Частичная загрузка может улучшить производительность в 10-50 раз, но требует значительной переработки. Рекомендуется начать с краткосрочных оптимизаций, затем постепенно переходить к частичной загрузке.
