# Удаление задержки синхронизации (debounce)

## Что было изменено

Убрана 5-секундная задержка (debounce) перед синхронизацией данных с сервером. Теперь синхронизация происходит **мгновенно** после каждого изменения.

## Проблема

Ранее при любом изменении данных (добавление, редактирование, удаление, перемещение) синхронизация с сервером происходила с задержкой 5 секунд. Это было сделано для оптимизации, чтобы объединять множественные быстрые изменения в один запрос.

**Недостатки:**
- Пользователь не видел изменений на сервере сразу
- При быстром закрытии страницы данные могли не сохраниться
- Неинтуитивное поведение для пользователей

## Решение

Удалён механизм debounce из функции `notify()` в `src/store.ts`.

### Было (с задержкой 5 секунд):

```typescript
function notify(reportId?: string, sectionId?: string) {
  saveData(reports);
  listeners.forEach(l => l());
  
  if (currentMode === 'api' && !isLoadingFromAPI) {
    if (syncTimeout) {
      clearTimeout(syncTimeout);
    }
    syncTimeout = setTimeout(() => {
      if (sectionId && reportId) {
        syncSectionToAPI(reportId, sectionId);
      } else if (reportId) {
        syncReportToAPI(reportId);
      } else {
        syncToAPI();
      }
      syncTimeout = null;
    }, 5000); // ← Задержка 5 секунд
  }
}
```

### Стало (мгновенная синхронизация):

```typescript
function notify(reportId?: string, sectionId?: string) {
  saveData(reports);
  listeners.forEach(l => l());
  
  if (currentMode === 'api' && !isLoadingFromAPI) {
    // Синхронизация происходит мгновенно без задержки
    if (sectionId && reportId) {
      syncSectionToAPI(reportId, sectionId);
    } else if (reportId) {
      syncReportToAPI(reportId);
    } else {
      syncToAPI();
    }
  }
}
```

## Изменения в коде

### Файл: `src/store.ts`

1. **Удалена переменная `syncTimeout`:**
   ```typescript
   // Было:
   let syncTimeout: ReturnType<typeof setTimeout> | null = null;
   
   // Стало: (удалено)
   ```

2. **Упрощена функция `notify()`:**
   - Убран `setTimeout` и `clearTimeout`
   - Синхронизация вызывается напрямую
   - Удалена задержка 5000 мс

## Преимущества

✅ **Мгновенная синхронизация** - изменения сразу отправляются на сервер  
✅ **Предсказуемое поведение** - пользователь видит результат сразу  
✅ **Надёжность** - данные не теряются при быстром закрытии страницы  
✅ **Проще код** - удалён механизм debounce и переменная `syncTimeout`

## Недостатки

⚠️ **Больше запросов к серверу** - каждое изменение отправляется отдельно  
⚠️ **Выше нагрузка на БД** - больше операций DELETE/INSERT

**Компенсация:**
- Оптимизированная синхронизация по разделам (5-20 КБ вместо 5+ МБ)
- Быстрые запросы (50-200 мс)
- Каскадное удаление в транзакции

## Производительность

### До (с debounce):

```
Изменение 1 → ожидание 5 сек → отправка всех данных (5+ МБ) → 2-5 сек
Изменение 2 → отмена таймера
Изменение 3 → отмена таймера
...
Изменение N → ожидание 5 сек → отправка всех данных (5+ МБ) → 2-5 сек
```

**Результат:** 1 запрос каждые 5 секунд, но большой объём данных

### После (без debounce):

```
Изменение 1 → мгновенная отправка раздела (5-20 КБ) → 50-200 мс
Изменение 2 → мгновенная отправка раздела (5-20 КБ) → 50-200 мс
Изменение 3 → мгновенная отправка раздела (5-20 КБ) → 50-200 мс
```

**Результат:** Много маленьких запросов, но каждый очень быстрый

### Сравнение

| Метрика | С debounce | Без debounce |
|---------|------------|--------------|
| Задержка | 5 секунд | Мгновенно |
| Объём запроса | 5+ МБ | 5-20 КБ |
| Время выполнения | 2-5 сек | 50-200 мс |
| Количество запросов | 1 раз в 5 сек | Каждый запрос |
| UX | Задержка | Мгновенный отклик |

## Проверка

### Тест 1: Мгновенная синхронизация

1. Откройте Network tab (F12)
2. Отредактируйте заметку
3. **Сразу** должен появиться запрос к `/api/report/{id}/section/{id}/sync`
4. НЕ должно быть задержки 5 секунд

### Тест 2: Множественные изменения

1. Быстро отредактируйте 3 элемента подряд
2. Должно быть **3 отдельных запроса** (не 1)
3. Каждый запрос должен отправиться **мгновенно**

### Тест 3: Логи консоли

В консоли браузера должны появиться:

```
Syncing single section: Название раздела
Sync section completed
```

**БЕЗ** сообщений о таймерах и задержках.

## Решение проблем

### Проблема: Задержка всё ещё есть

**Решение:**
1. Очистите кэш браузера (Ctrl + Shift + Delete)
2. Убедитесь, что загружен обновлённый `store.ts`
3. Перезагрузите страницу (Ctrl + F5)

### Проблема: Слишком много запросов к серверу

**Решение:**
Это ожидаемое поведение. Каждый запрос очень быстрый (50-200 мс) и маленький (5-20 КБ), поэтому нагрузка минимальна.

Если нужно уменьшить количество запросов, можно вернуть debounce с меньшей задержкой (например, 1 секунда):

```typescript
syncTimeout = setTimeout(() => {
  // синхронизация
}, 1000); // 1 секунда вместо 5
```

### Проблема: Ошибки синхронизации

**Решение:**
1. Проверьте логи PHP: `C:\web\Apache24\logs\error.log`
2. Проверьте Network tab на наличие ошибок
3. Убедитесь, что сервер работает корректно
