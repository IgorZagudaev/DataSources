# Откат изменений до состояния DISABLE_DEBUG_LOGS.md

## Описание

Выполнен откат всех изменений, связанных с переработкой фронтенда на REST API, до состояния, описанного в документе `DISABLE_DEBUG_LOGS.md`.

## Что было откатано

### Удалено:

1. **Частичная загрузка данных (Partial Loading)**
   - Удалена функция `loadHierarchy()` из `store.ts`
   - Удалены функции `updateLocalState()`, `deepMerge()`, `mergeHierarchy()` и другие функции слияния
   - Удалён endpoint `/api/{level}/{id}/hierarchy` из PHP API
   - Удалена функция `fetchHierarchy()` из `api.ts`

2. **Прямые вызовы REST API для CRUD операций**
   - Все функции в `store.ts` теперь работают через localStorage + синхронизацию
   - Удалены прямые вызовы `api.updateReport()`, `api.addSection()` и т.д.
   - Восстановлена синхронизация через `/api/import`

3. **Оптимизации производительности**
   - Удалён debounce для синхронизации
   - Удалено логирование времени выполнения операций
   - Удалены оптимистичные обновления

### Восстановлено:

1. **Гибридный режим работы**
   - Восстановлен `ModeSwitcher` для переключения между localStorage и PostgreSQL
   - Восстановлена функция `syncFromAPI()` для загрузки данных из БД
   - Восстановлена функция `syncToAPI()` для синхронизации данных с БД
   - Восстановлен флаг `isLoadingFromAPI` для предотвращения обратной синхронизации

2. **localStorage как основное хранилище**
   - Все данные хранятся в localStorage
   - При изменении данных вызывается `notify()`, который сохраняет в localStorage
   - В режиме API данные синхронизируются с сервером через `/api/import`

3. **Полная загрузка данных**
   - Функция `loadReports()` загружает все данные из API
   - После каждого изменения вызывается полная синхронизация
   - Нет частичной загрузки - всегда загружается весь доклад

4. **CRUD операции через localStorage**
   - Все функции `addReport()`, `updateReport()`, `deleteReport()` и т.д. работают с localStorage
   - После изменения вызывается `notify()`, который синхронизирует с сервером
   - Нет прямых вызовов API для каждой операции

## Архитектура после отката

### Поток данных:

```
Пользователь → UI → Store (localStorage) → notify() → syncToAPI() → POST /api/import
                                                         ↓
Пользователь ← UI ← Store (localStorage) ← notify() ← syncFromAPI() ← GET /api/reports
```

### Режимы работы:

**Локальный режим:**
- Данные хранятся только в localStorage
- Нет синхронизации с сервером
- Быстрая работа, но данные теряются при очистке браузера

**Режим PostgreSQL:**
- Данные хранятся в localStorage И в PostgreSQL
- При каждом изменении данные синхронизируются с сервером
- При загрузке страницы данные загружаются из сервера
- Медленнее, но данные сохраняются между сессиями

## Производительность после отката

### Текущая производительность:

| Операция | Время | Объём данных | SQL запросов |
|----------|-------|--------------|--------------|
| Изменение источника | 2-5 сек | 5+ МБ | 10+ (DELETE + INSERT) |
| Добавление справки | 2-5 сек | 5+ МБ | 10+ (DELETE + INSERT) |
| Перемещение показателя | 2-5 сек | 5+ МБ | 10+ (DELETE + INSERT) |

### Почему медленно:

1. **Полная синхронизация** - при каждом изменении отправляются все данные
2. **DELETE + INSERT** - PHP API удаляет все таблицы и вставляет все данные заново
3. **Нет оптимизаций** - нет debounce, нет кэширования, нет оптимистичных обновлений

### Преимущества отката:

1. **Простота** - простая архитектура, легко понимать и отлаживать
2. **Надёжность** - данные всегда синхронизированы между клиентом и сервером
3. **Совместимость** - работает с существующим PHP API без изменений
4. **Гибридный режим** - можно работать без сервера (локальный режим)

## Решение проблем

### Проблема: Данные не синхронизируются с сервером

**Решение:**
1. Убедитесь, что выбран режим "PostgreSQL"
2. Проверьте консоль браузера на наличие ошибок
3. Проверьте логи PHP в `C:/web/Apache24/logs/error.log`
4. Проверьте, что endpoint `/api/import` работает

### Проблема: Данные теряются при обновлении страницы

**Решение:**
1. Убедитесь, что выбран режим "PostgreSQL"
2. Проверьте, что данные сохраняются в БД
3. Проверьте функцию `syncToAPI()` в `store.ts`

### Проблема: Медленная работа

**Решение:**
1. Это ожидаемое поведение после отката
2. Рассмотрите возможность повторной оптимизации в будущем
3. Используйте локальный режим для быстрой работы
